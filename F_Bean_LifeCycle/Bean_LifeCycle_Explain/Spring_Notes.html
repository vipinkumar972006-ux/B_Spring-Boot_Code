📚 Section 1: Spring Core

1.1 Spring Framework Kya Hai?

Definition: Spring Framework ek open-source Java framework hai jo enterprise applications banane ke liye use hota hai. Ye lightweight, modular, aur flexible hai.

Key Features:

  • Lightweight: Minimal overhead, fast startup
  • Modular: Only use what you need
  • Loose Coupling: IoC aur DI se components decouple hote hain
  • Testability: Easy unit testing with mock objects
  • Transaction Management: Declarative transactions
  • MVC Framework: Built-in web framework
  • Security: Spring Security integration

Spring Modules:

ModuleDescription
Core ContainerIoC, DI, Beans, Events
Data Access/IntegrationJDBC, ORM, JMS, Transactions
WebMVC, REST, WebSocket
AOPAspect-Oriented Programming
InstrumentationClassloading, Monitoring
TestUnit & Integration Testing

Spring Architecture:

┌─────────────────────────────────────────┐ │ Spring Framework │ ├─────────────────────────────────────────┤ │ Test ← Integration with JUnit/TestNG │ ├─────────────────────────────────────────┤ │ Web ← MVC, REST, WebSocket, Portlet │ ├─────────────────────────────────────────┤ │ AOP ← Aspect-Oriented Programming │ ├─────────────────────────────────────────┤ │ MVC ← Web MVC Framework │ ├─────────────────────────────────────────┤ │ Data Access ← JDBC, ORM, OxM, JMS │ ├─────────────────────────────────────────┤ │ Business ← Transactions, Validation │ ├─────────────────────────────────────────┤ │ Core ← Beans, Core, Context, SpEL │ └─────────────────────────────────────────┘

1.2 Inversion of Control (IoC)

IoC Principle: Traditional programming mein hum objects khud create karte hain. IoC mein ye responsibility framework ko de dete hain.

Traditional Approach (Before IoC):

// Traditional - Tight Coupling public class Car { private Engine engine = new Engine(); // Khud create kar rahe hain public void start() { engine.start(); } }

IoC Approach:

// IoC - Loose Coupling public class Car { private Engine engine; // Framework inject karega public Car(Engine engine) { // Constructor Injection this.engine = engine; } public void start() { engine.start(); } }
Key Point: IoC ka matlab hai control ki inversion — object creation aur wiring ka control application se hata kar framework ko de diya jata hai.

IoC Container:

  • Spring ka IoC container objects create karta hai
  • Dependencies inject karta hai
  • Objects ka lifecycle manage karta hai
  • Do types: BeanFactory aur ApplicationContext

1.3 Dependency Injection (DI)

DI Definition: Dependency Injection IoC ka ek pattern hai jisme dependencies external source se provide hoti hain, object khud create nahi karta.

DI ke 3 Types:

1. Constructor Injection:

@Service public class UserService { private final UserRepository userRepository; @Autowired public UserService(UserRepository userRepository) { this.userRepository = userRepository; } }

2. Setter Injection:

@Service public class UserService { private UserRepository userRepository; @Autowired public void setUserRepository(UserRepository userRepository) { this.userRepository = userRepository; } }

3. Field Injection:

@Service public class UserService { @Autowired private UserRepository userRepository; // Direct field injection }
Best Practice: Constructor Injection sabse recommended hai kyunki: - Objects immutable hote hain - Null checks nahi chahiye - Testing easy hota hai - Circular dependency detect hota hai

1.4 Spring Bean

Bean Definition: Spring Bean ek Java object hai jo Spring IoC container manage karta hai. Ye application ka fundamental building block hai.

Bean Registration Methods:

1. @Component Annotation:

@Component public class MyService { // Spring automatically detect aur manage karega }

2. @Bean Annotation:

@Configuration public class AppConfig { @Bean public MyService myService() { return new MyService(); } }

3. Component Scanning:

@ComponentScan("com.example.service") public class AppConfig { // Saare @Component annotated classes scan hongi }

Bean Stereotype Annotations:

@ServiceServiceBusiness logic layer
@RepositoryDAOData access layer, exception translation
@ControllerWebMVC controller layer

1.6 Bean Lifecycle

Bean Lifecycle: Spring bean ke creation se le kar destruction tak ke saare steps ko bean lifecycle kehte hain.

Complete Lifecycle Steps:

┌──────────────────────────────────────────────┐ │ BEAN LIFECYCLE FLOW │ ├──────────────────────────────────────────────┤ │ │ │ 1. Object Creation (Instantiation) │ │ ↓ │ │ 2. Dependency Injection (@Autowired) │ │ ↓ │ │ 3. @PostConstruct Method Call │ │ ↓ │ │ 4. BeanPostProcessor (before) │ │ ↓ │ │ 5. Bean is Ready (Use Phase) │ │ ↓ │ │ 6. BeanPostProcessor (after) │ │ ↓ │ │ 7. @PreDestroy Method Call │ │ ↓ │ │ 8. Bean Destruction │ │ │ └──────────────────────────────────────────────┘

Lifecycle Callbacks:

@Component public class MyBean { // 1. Constructor public MyBean() { System.out.println("Step 1: Object created"); } // 2. @PostConstruct - After dependency injection @PostConstruct public void init() { System.out.println("Step 3: Initialization"); } // 3. @PreDestroy - Before bean destruction @PreDestroy public void cleanup() { System.out.println("Step 7: Cleanup"); } }

InitializingBean & DisposableBean:

@Component public class MyBean implements InitializingBean, DisposableBean { @Override public void afterPropertiesSet() throws Exception { // @PostConstruct ke baad call hota hai System.out.println("InitializingBean callback"); } @Override public void destroy() throws Exception { // @PreDestroy se pehle call hota hai System.out.println("DisposableBean callback"); } }

BeanPostProcessor:

@Component public class MyPostProcessor implements BeanPostProcessor { @Override public Object postProcessBeforeInitialization(Object bean, String beanName) { // @PostConstruct se pehle System.out.println("Before: " + beanName); return bean; } @Override public Object postProcessAfterInitialization(Object bean, String beanName) { // @PostConstruct ke baad System.out.println("After: " + beanName); return bean; } }

1.7 @PostConstruct & @PreDestroy

@PostConstruct: Bean create hone ke baad aur use hone se pehle automatically execute hota hai. Initialization ke liye use hota hai.
@PreDestroy: Bean ko destroy karne se pehle automatically execute hota hai. Cleanup ke liye use hota hai.

Complete Example:

@Service public class DatabaseService { private Connection connection; @PostConstruct public void initialize() { // Bean ready hone ke baad connection open karo connection = DriverManager.getConnection(url); System.out.println("Database connected!"); } public void processData() { // Business logic } @PreDestroy public void cleanup() { // Container close hone se pehle connection close karo if (connection != null) { connection.close(); } System.out.println("Database disconnected!"); } }

Execution Order:

Constructor → @Autowired → @PostConstruct → [Bean Use] → @PreDestroy → Destroy

2.1 Spring MVC

Spring MVC: Model-View-Controller pattern par based web framework hai jo Spring ka part hai.

Architecture:

┌─────────────────────────────────────────────┐ │ Spring MVC Architecture │ ├─────────────────────────────────────────────┤ │ │ │ Client → DispatcherServlet │ │ ↓ │ │ HandlerMapping → Controller │ │ ↓ │ │ Controller → Service → Repository │ │ ↓ │ │ ViewResolver → View → Response │ │ │ └─────────────────────────────────────────────┘

Key Components:

ComponentRole
DispatcherServletFront controller, sab requests handle karta hai
HandlerMappingRequest ko appropriate controller se map karta hai
ControllerBusiness logic handle karta hai
ModelData hold karta hai
ViewResolverView name se actual view find karta hai
ViewResponse render karta hai

Controller Example:

@Controller @RequestMapping("/users") public class UserController { @Autowired private UserService userService; @GetMapping public String getAllUsers(Model model) { List users = userService.getAllUsers(); model.addAttribute("users", users); return "user-list"; // View name } @GetMapping("/{id}") public String getUser(@PathVariable Long id, Model model) { User user = userService.getUserById(id); model.addAttribute("user", user); return "user-detail"; } @PostMapping public String createUser(@RequestBody User user) { userService.saveUser(user); return "redirect:/users"; } }

@RequestMapping Variants:

@GetMapping // HTTP GET @PostMapping // HTTP POST @PutMapping // HTTP PUT @DeleteMapping // HTTP DELETE @PatchMapping // HTTP PATCH

2.2 Spring AOP

AOP (Aspect-Oriented Programming): Cross-cutting concerns (logging, security, transactions) ko separate code mein isolate karta hai.

Key Concepts:

TermDescription
AspectCross-cutting concern (Logging, Security)
Join PointMethod execution, exception handling
AdviceAction taken at join point
PointcutExpression that matches join points
WeavingAspect ko application se connect karna
ProxyAspect-enabled object

Advice Types:

@Aspect @Component public class LoggingAspect { // Before - Method se pehle @Before("execution(* com.example.service.*.*(..))") public void logBefore(JoinPoint joinPoint) { System.out.println("Before: " + joinPoint.getSignature()); } // After Returning - Method success hone ke baad @AfterReturning(pointcut = "execution(* com.example.service.*.*(..))", returning = "result") public void logAfterReturning(Object result) { System.out.println("Result: " + result); } // After Throwing - Exception aane pe @AfterThrowing(pointcut = "execution(* com.example.service.*.*(..))", throwing = "ex") public void logException(Exception ex) { System.out.println("Exception: " + ex.getMessage()); } // After - Hamesha execute hota hai @After("execution(* com.example.service.*.*(..))") public void logAfter() { System.out.println("After method execution"); } // Around - Pehle aur baad dono @Around("execution(* com.example.service.*.*(..))") public Object logAround(ProceedingJoinPoint joinPoint) throws Throwable { long start = System.currentTimeMillis(); Object result = joinPoint.proceed(); long end = System.currentTimeMillis(); System.out.println("Time: " + (end - start) + "ms"); return result; } }

2.4 Spring Security

Spring Security: Authentication aur Authorization provide karta hai. Application ko secure banata hai.

Security Configuration:

@Configuration @EnableWebSecurity public class SecurityConfig { @Bean public SecurityFilterChain filterChain(HttpSecurity http) throws Exception { http .csrf().disable() .authorizeHttpRequests(auth -> auth .requestMatchers("/public/**").permitAll() .requestMatchers("/admin/**").hasRole("ADMIN") .requestMatchers("/user/**").hasAnyRole("USER", "ADMIN") .anyRequest().authenticated() ) .httpBasic(Customizer.withDefaults()); return http.build(); } @Bean public PasswordEncoder passwordEncoder() { return new BCryptPasswordEncoder(); } @Bean public UserDetailsService userDetailsService() { UserDetails user = User.builder() .username("user") .password(passwordEncoder().encode("password")) .roles("USER") .build(); return new InMemoryUserDetailsManager(user); } }

JWT Authentication:

// JWT Filter @Component public class JwtAuthFilter extends OncePerRequestFilter { @Override protected void doFilterInternal( HttpServletRequest request, HttpServletResponse response, FilterChain filterChain) { String header = request.getHeader("Authorization"); if (header != null && header.startsWith("Bearer ")) { String token = header.substring(7); String username = jwtService.extractUsername(token); if (username != null) { Authentication auth = new UsernamePasswordAuthenticationToken( username, null, Collections.emptyList() ); SecurityContextHolder.getContext().setAuthentication(auth); } } filterChain.doFilter(request, response); } }

2.5 Spring Transaction Management

Transaction Management: Database operations ko ACID properties ke saath manage karta hai.

Declarative Transactions:

@Service @Transactional public class OrderService { @Autowired private OrderRepository orderRepository; @Autowired private PaymentRepository paymentRepository; // @Transactional - Both operations ek transaction mein public void placeOrder(Order order, Payment payment) { orderRepository.save(order); paymentRepository.save(payment); // Agar exception aaya, to dono rollback honge } // Read-only transaction @Transactional(readOnly = true) public List getOrders() { return orderRepository.findAll(); } // Custom rollback @Transactional(rollbackFor = CustomException.class) public void processOrder(Order order) { // CustomException pe rollback hoga } }

Transaction Propagation:

PropagationDescription
REQUIREDExisting transaction use karo, nahi to naya banao (Default)
REQUIRES_NEWHamesha naya transaction banao
SUPPORTSTransaction ho to use karo, nahi to without bhi chalo
NOT_SUPPORTEDTransaction ke bina chalo
MANDATORYExisting transaction chahiye, nahi to exception
NEVERTransaction ke bina chalo, transaction ho to exception
NESTEDNested transaction - savepoints use karta hai

📚 Section 3: Spring Boot

3.1 Spring Boot Kya Hai?

Spring Boot: Spring Framework ka extension hai jo rapid application development ke liye bana hai. "Opinionated" approach follow karta hai — sensible defaults provide karta hai.

Key Features:

  • Auto Configuration: Automatic configuration based on classpath
  • Starter Dependencies: Pre-configured dependency sets
  • Embedded Servers: Tomcat, Jetty, Undertow embedded
  • Actuator: Production-ready monitoring
  • CLI: Command-line interface for rapid development
  • No Code Generation: Pure Java configuration
  • No XML Configuration: Zero XML needed

Spring vs Spring Boot:
